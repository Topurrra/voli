v0.12.3

2026-08-01 current
  • A read inside a project now also shows the user's global core - the pinned facts from the machine-wide store, in their own section headed From your global memory. Both voli memory read and the session-start hook carry it, and the hook no longer stays silent when the project's own store is empty but there is global core to show, so a freshly set up project still arrives with the standing rules. Before, a session inside a codebase loaded only that project's store, and the user's machine-wide rules for how they work never reached it.
  • The borrowed core runs through the same fence and disclosure firewall as a local memory, so a masked secret stays masked and a --private note stays withheld - even though a different store decrypted it under its own key.
  • The rule for keeping the two stores apart is now one shared line, quoted verbatim by the four places that state it: the hook preamble, the setup prompt, the MCP memory_note tool, and the companion skill. A test fails if any copy drifts. It says to read the global core for context, save what belongs to this codebase in the project store and what belongs to the user in the global one with --global, and never copy a memory from one store into the other.
  • On the MCP path, memory_note gained a global: true option, so an agent can record a machine-wide fact from inside a project. An explicit $VOLI_MEMORY_DIR still pins the store exactly and suppresses the global-core borrow.

v0.12.2

2026-08-01
  • The memory commands are coloured in a terminal - ids in amber, because those are what you retype into --supersedes; dates and tags dimmed. The memory text stays plain, so colour keeps meaning what it already meant there: a masked secret or a withheld note.
  • voli memory stats now reports records it could not decrypt. The skip was always deliberate - one bad record must not blind a whole store - but it was silent, so every command a person actually runs under-reported while verify counted the full set.

v0.12.1

2026-08-01
  • voli memory init stops printing the whole setup prompt. Seventy lines buried the one thing the command was run for; it now names the three ways to wire an agent instead.
  • The session-start hook injects nothing when the store is empty, rather than spending an agent's context to say there is no context.
  • voli memory prompt git-ignores the file it writes - it is generated, so a committed copy only goes stale.

v0.12.0

2026-08-01
  • voli memory hook writes the settings file for you. Pick --project-local, --project-shared or --global and it edits that file in place instead of printing a block to paste. It merges into whatever hooks are already there, running it twice is a no-op, and --remove takes it back out. A settings file that does not parse is refused rather than rewritten - a broken one silently disables every setting in it.
  • voli memory init now makes a store for the codebase you are in, like git init. --global makes the machine-wide one instead. A behaviour change, so the first run names the other option rather than letting you find out later.
  • One containment rule, not three. The rule telling an agent that memories are records and never instructions lived in three places and had drifted apart in substance - the copy in the MCP tool descriptions, which an agent sees on every request, had lost the exfiltration vector entirely. Now one constant, with a test that fails if a copy stops matching it.
  • init honours $VOLI_MEMORY_DIR again, and says "created" on a first run rather than "found".

v0.11.0

2026-08-01
  • voli memory serve --mcp - serves the encrypted memory to an agent over MCP, so it reads and writes with native tools instead of shelling out. An instruction telling an agent to check its memory decays: it scrolls out of context and dies at compaction. A tool definition does not, because the harness re-sends the tool list on every request.
  • voli memory hook - prints the session-start hook that loads memory before the agent decides anything. The one layer that does not depend on a model remembering.
  • A companion skill - voli install skill/voli-memory - for the part that genuinely needs judgement: what earns a note, supersede versus retract, what must never be written down at all.
  • A leak, fixed. The contradiction warning quoted the memory it clashed with verbatim, so a key came back unmasked and a --private memory came back in full - both of which read correctly hides. Harmless-looking when a human sees their own secret in their own terminal; not harmless once an agent receives it and carries it onward.
  • Progress marks keep their colour when only stdout is piped, and a long-standing test race is gone.

v0.10.0

2026-07-31
  • voli web - open a search shortcut in your browser. Voli builds the URL and fetches nothing, so there is no API key, no quota, and nothing to bot-block.
  • voli fetch - retrieve a page as text, Markdown, or JSON with the provenance to prove what was read: final URL, timestamp, sha256, and byte length.
  • Package aliases - a renamed package keeps answering to its old name, so a rename no longer strands the people who installed it.
  • arm64 is real - [source.arm64] used to be inert, with every install path hardcoding x64. Host architecture is now detected at runtime.
  • One canonical manifest form - serialization had drifted across three emitters; 288 manifests were normalized to a single shape, with no change of meaning to any of them.
  • python is now python-embed, because it installs the embeddable build: no pip, no venv. The old name still resolves.

v0.1.0

2026-07-24 first release
  • The install engine - transactional install and uninstall, recorded in a ledger that delete replays backwards. That is the zero-trace guarantee, by construction.
  • The signed index - an Ed25519-signed sqlite snapshot with full-text search, resumable cached downloads, dependency resolution, and did-you-mean on a miss.
  • upgrade, pin, cleanup, doctor, config, and a consent flow for environment variables.
  • Self-install with user-level PATH setup - no admin, at any point.
  • The one-line installer and volibear.dev.
Pre-1.0. Commands and the manifest schema may still change before v1. Versions before then are not a stability promise - but the four guarantees (no admin, clean uninstall, no scripts, and everything pinned) have held since v0.1.0 and are not up for negotiation.
